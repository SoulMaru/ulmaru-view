# 얼마루 뷰 (ulmaru-view)

로컬에 있는 얼마루 미디어(영상·오디오·이미지)를 탐색하고 브라우저에서 재생하는 작은 뷰어입니다. 외부 의존성 없이 Node 22 표준 라이브러리만 쓰며, 기본은 `127.0.0.1`에만 열립니다.

## 기능

- **로컬 미디어 탐색**: 지정한 폴더를 재귀 탐색해 영상·오디오·이미지를 모읍니다. 숨김 폴더·`node_modules`·휴지통은 건너뜁니다.
- **목록**: 이름·폴더 검색, 종류 필터(전체/영상/오디오/이미지), 더 보기.
- **재생**: 재생·일시정지, 탐색 바, 볼륨, 음소거. HTTP Range 스트리밍으로 큰 파일도 바로 재생합니다.
- **마우스 휠 볼륨**: 재생 화면에서 휠을 위로 굴리면 **+5**, 아래로 굴리면 **-5**. 0~100에서 멈춥니다.
- **전체화면 상단 X**: 전체화면일 때 마우스를 화면 상단으로 올리면 상단 바와 **X**가 나타납니다. X를 누르면 전체화면이 끝납니다.
- **키보드**: `Enter` 전체화면 토글, `Esc` 전체화면 종료, `Space` 재생/일시정지, `↑/↓` 볼륨 ±5, `←/→` 5초 이동.
- **로컬 전용**: 기본 바인딩 `127.0.0.1`. 외부 스크립트·CDN을 쓰지 않습니다.

## 실행

```bash
cd ulmaru-view
npm start                       # http://127.0.0.1:8793
```

미디어 폴더를 직접 지정하려면:

```bash
ULMARU_MEDIA_ROOT="/mnt/c/AI_RUNTIME_PC1/04_CONTENT_STUDIO" npm start
```

환경변수:

| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `8793` | HTTP 포트 |
| `HOST` | `127.0.0.1` | 바인딩 주소(로컬 전용 권장) |
| `ULMARU_MEDIA_ROOT` | 아래 후보 중 첫 폴더 | 미디어를 읽을 폴더 |
| `ULMARU_CACHE_DIR` | `~/.cache/ulmaru-view` | 색인 캐시를 저장할 폴더 |

미디어 폴더 후보(앞에서부터 존재하는 첫 폴더):

1. `ULMARU_MEDIA_ROOT`
2. `/mnt/c/AI_RUNTIME_PC1/04_CONTENT_STUDIO`
3. `~/soulmaru-2/downloads`
4. `./media`

## 조작

| 입력 | 동작 |
|---|---|
| 마우스 휠 (재생 화면) | 볼륨 ±5 |
| `Enter` | 전체화면 토글 |
| `Esc` | 전체화면 종료 |
| `Space` | 재생/일시정지 |
| `↑` / `↓` | 볼륨 ±5 |
| `←` / `→` | 5초 뒤로 / 앞으로 |
| 화면 클릭 | 재생/일시정지 |
| 목록 클릭 | 해당 미디어 재생 |

전체화면에서 마우스를 상단(≤96px)으로 올리면 X가 나타나고, 2.4초 뒤 사라집니다. X에 마우스를 올리면 유지됩니다.

## API

| 경로 | 설명 |
|---|---|
| `GET /api/state` | 미디어 폴더, 전체 개수, 종류별 개수, 스캔 시각 |
| `GET /api/media?q=&kind=&offset=&limit=&refresh=1` | 목록(최신 수정순). `refresh=1`은 캐시를 무시하고 다시 읽습니다. |
| `GET /api/stream/:id` | 파일 스트리밍(Range 지원). `id`는 상대 경로의 해시 |
| `GET /api/health` | 상태 확인 |

인덱스는 60초 동안 메모리 캐시하고, 디스크(`ULMARU_CACHE_DIR`)에도 저장합니다. 서버를 다시 켜면 디스크 색인을 즉시 돌려주고 뒤에서 새로 읽습니다(기본 42ms 응답). 파일이 추가·삭제되면 화면의 **새로고침**을 누르거나 `refresh=1`을 씁니다.

## 성능

- 파일 `stat`을 32개씩 병렬로 읽습니다. Windows 드라이브(9p)에서 13,919개 기준 첫 스캔 **54초 → 9초**.
- 디스크 색인(4MB)이 있으면 재시작 후 첫 응답이 **42ms**입니다.
- 목록은 200개씩 나눠 보내고, 재생은 Range 스트리밍이라 큰 파일도 바로 시작합니다.

## 구조

| 파일 | 역할 |

| `server.mjs` | HTTP 서버, 정적 파일, 목록 API, Range 스트리밍 |

| `public/styles.css` | 다크 시네마 테마, 전체화면·반응형 |
| `public/app.js` | 목록·재생·휠 볼륨·전체화면·키보드 |
| `test/*.test.mjs` | 순수 로직·HTTP·정적 계약 시험 |
| `tools/smoke.mjs` | 실제 Chromium 스모크(선택, playwright-core 필요) |

```bash

```

스모크는 다음을 확인합니다: WebGL 없이도 동작하는 목록·재생, 휠 볼륨 ±5, `Enter` 전체화면, 상단 X 표시·클릭 종료, `Esc` 종료, 브라우저 콘솔 오류 0.

## 보안 경계

- 기본 `127.0.0.1` 바인딩. `HOST=0.0.0.0`은 명시적으로 지정할 때만 열립니다.
- 스트리밍은 인덱스에 등록된 파일만, 미디어 폴더 밖 경로는 거부합니다.
- 쓰기 API가 없습니다(GET/HEAD만).
- 미디어 파일은 저장소에 커밋하지 않습니다.
